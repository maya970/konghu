# 空毂

Windows 上的 EVM 转账钱包。只做两件事：主币转账，以及 ERC-20 的 `transfer(address,uint256)`。没有 DApp 连接，没有授权，没有任意签名。

双击桌面上的「空毂」，或双击 `打开\空毂.exe`。会打开三扇窗口：

| 窗口 | 程序 | 作用 |
| --- | --- | --- |
| 空毂 | `打开\空毂.exe` | 入口。按钮可以再次打开下面两扇 |
| 清机 — 空毂 | 同目录 `qing.exe` | 保险库、助记词、核对、签名。无网络请求 |
| 浊机 — 空毂 | 同目录 `zhuo.exe` | 选链、填金额、写简牍、广播。无种子 |

清机和浊机是两个进程。种子只在清机进程里出现。浊机进程不链接签名代码。两边不走剪贴板，不互相发窗口消息，只通过一个目录里的两个文件交接。

## 完成一笔转账

下面按第一次使用来写。以后跳过创建保险库，从解锁开始。

### 1. 打开

双击桌面「空毂」。三扇窗口都出现后，日常操作只看清机和浊机。

清机第一次打开时，给两边填同一个投递目录，例如 `C:\KonghuDrop`。这个目录需要事先建好，并且当前用户能在里面创建文件。清机点「保存」。浊机的投递目录填同一路径，点「保存设置」。

### 2. 在清机创建保险库

清机窗口上方是两个口令框，下面是「创建」「解锁」「锁定」。

1. 口令输入两次。长度 8 到 128 个字符。两次不一致不会写入。
2. 点「创建」。已有保险库时清机拒绝覆盖。
3. 中间的只读文本框显示 12 个英文单词。这是唯一一次显示。抄到清机所在机器以外的地方，再点「锁定」。
4. 口令只用来解开本机文件 `%USERPROFILE%\.konghu\vault.khuv`。它不是助记词的第 25 个词，不能单独拿去在别的钱包恢复。恢复账户用的是这 12 个词。

保险库是 `KHUV` 版本 1，长度固定。口令用 Argon2id 派生，内存 19 MiB，迭代 2 次，并行度 1。文件头里的参数若被改成别的值，清机直接拒绝打开，不会按被改过的参数去派生。密文是 ChaCha20-Poly1305。磁盘上没有熵的明文。

### 3. 解锁，把付款地址抄到浊机

1. 清机输入口令，点「解锁」。文本框出现付款地址，形如 `0x` 加 40 位十六进制，带 EIP-55 大小写。
2. 把这个地址抄进浊机的「付款地址」。浊机用它向节点查 nonce，不拿它签名。
3. 清机解锁之后，种子在该进程里保留到下一次成功签名或点「锁定」。不要让清机停在已解锁状态。

派生路径固定为 `m/44'/60'/0'/0/0`。简牍不能改路径，也不能改账户索引。所有 EVM 链共用这一个地址。

### 4. 在浊机填写这笔转账

浊机左侧是链列表，来自程序旁边的 `evm.json`（没有外部文件时用编译进浊机的那一份）。点一条链。右侧「节点」显示该链的 RPC，只读。浊机会请求这个节点，并核对该节点返回的链编号与列表里的编号一致。不一致则不写简牍。

主币：

1. 「收款地址」填 `0x` 加 40 位十六进制。
2. 「数量」按人类单位填，例如 `0.01`。小数位用链登记里的值。
3. 不要勾选代币。
4. 点「写入简牍」。

代币：

1. 勾选「这是代币转账（只做 transfer，不做授权）」。
2. 「代币合约」填合约地址。
3. 「代币小数位」填该合约的小数位。USDT 通常是 6，不是默认的 18。填错会让最小单位差 10 的若干次方。清机不会帮你改这个数。
4. 「收款地址」和「数量」照填。点「写入简牍」。

写入成功后，浊机状态框给出链编号、最小单位数量和费用上限。同时发生两件事：投递目录出现 `inbox.khub`；浊机配置目录 `%USERPROFILE%\.konghu-zhuo\` 留下待广播副本。旧的 `outbox.khur` 会被删掉，避免广播上一笔的回执。

费用由浊机向节点查询后写入简牍。有 `baseFee` 时，`max_fee_per_gas` 取两倍基础费加优先费，否则取两倍 `gasPrice`。主币 gas 固定 21000，代币 gas 固定 120000。零费用链写成 1 wei，否则简牍会因单价为零被拒绝。

### 5. 在清机核对并签名

回到清机，点「读取简牍」。中间文本框显示清机自己解析出的字段，而不是浊机状态框里的句子：

- 链编号（数字，没有链的宣传名）
- 付款地址、收款地址（EIP-55 全长）
- 主币，或代币合约全长地址
- 数量，最小单位整数，不换算小数
- 费用上限，以及实际封顶 `gas_limit × max_fee_per_gas`
- nonce、gas、两种单价、过期时间

过期时间由浊机设为写入时刻之后 15 分钟。清机拒绝已过期的简牍，也拒绝离现在超过 30 分钟的简牍。超时就回浊机重新写入。

本地备注是可选的。文件在 `%USERPROFILE%\.konghu\labels.txt`，一行一条：`40位十六进制地址`、空格、不超过 32 个字符的备注。清机只在地址对得上时把备注附在该地址下面。含控制字符、双向覆盖或零宽字符的行会被丢掉。备注不能代替地址核对。

核对之后，在底部输入框按**转账前自己记下的数字**输入确认串。这个框拒绝粘贴。

主币：

```text
链编号/数量/实际封顶/收款地址
```

代币在实际封顶和收款地址之间加上合约：

```text
链编号/数量/实际封顶/代币合约/收款地址
```

数量和实际封顶都是最小单位的十进制，不要写成 `0.01` 这种人类单位。地址是 40 位十六进制，不带 `0x`，大小写都可以。例子：向地址 `0x1111…1111` 转 1 wei，实际封顶 42000 wei，链编号 1：

```text
1/1/42000/1111111111111111111111111111111111111111
```

串和清机解析出的简牍一致时，「签名」按钮才可按。点「签名」。清机把回执写到投递目录的 `outbox.khur`，然后从内存清掉种子，并在简牍文件仍是刚刚这一张时删掉 `inbox.khub`。状态框显示种子已清掉。要签下一笔，必须重新解锁。

不要照着清机窗口抄确认串。窗口可以被另一层程序盖住。确认串的作用是让你打出转账之前就已经确定的链、数量、费用和全长地址。

确认串不包含 nonce。经济字段相同的第二张简牍会通过同一句确认串。每次签名前仍要看清机文本框里的 nonce 和过期时间。

### 6. 在浊机广播

切回浊机，点「广播回执」。浊机只在同时满足下面两条时调用 `eth_sendRawTransaction`：

1. 回执里的简牍字节等于刚才「写入简牍」留下的那一张。
2. 回执里的已签名交易解出来之后，链编号、nonce、费用、收款、金额和调用数据与简牍一致。

状态框给出交易哈希。程序不会打开浏览器。节点拒绝（nonce 已用过、余额不足、gas 不够）时，错误显示在状态框，清机不会自动重签。

## 签名程序实际签了什么

清机不接受 32 字节摘要。没有 `eth_sign`，没有 `personal_sign`，没有 EIP-712。浊机交过来的只有 207 字节定长简牍，魔数 `KHUB`，版本 1。多一字节或少一字节都拒绝。

| 偏移 | 长度 | 字段 | 拒绝条件 |
| --- | --- | --- | --- |
| 0 | 4 | `KHUB` | 魔数不对 |
| 4 | 1 | 版本 | 不是 1 |
| 5 | 1 | 家族 | 不是 1（EVM） |
| 6 | 8 | 链编号 | 为 0 |
| 14 | 1 | 资产种类 | 不是 1 或 2 |
| 15 | 20 | 代币合约 | 主币时非全零；代币时全零，或与收款地址相同 |
| 35 | 20 | 收款地址 | 全零 |
| 55 | 32 | 数量，最小单位 | 零 |
| 87 | 32 | 费用上限 | 小于 `gas_limit × max_fee_per_gas` |
| 119 | 8 | 过期，unix 秒 | 不在现在起 30 分钟以内 |
| 127 | 8 | nonce | |
| 135 | 8 | gas_limit | 0，或大于 200000 |
| 143 | 32 | max_fee_per_gas | 零，或低于优先费 |
| 175 | 32 | max_priority_fee_per_gas | |

清机用这些字段自己组装 EIP-1559 交易，类型字节 `0x02`，访问列表为空：

- 主币：`to` 为收款地址，`value` 为数量，calldata 为空。
- 代币：`to` 为合约，`value` 为 0，calldata 恰好 68 字节。选择子是 `keccak256("transfer(address,uint256)")` 的前 4 字节 `a9059cbb`，随后是左填充的收款地址和 32 字节数量。

`approve` 的选择子 `095ea7b3` 没有编码路径。简牍里也没有自由 calldata 字段，因此不能签任意合约调用，也不能签 `permit`。

待签名哈希是这串未签名交易的 Keccak-256。签名是 secp256k1，低 `s`。清机把签名装回交易后再解码，字段必须与简牍一致；用签名恢复出的地址必须等于种子在 `m/44'/60'/0'/0/0` 上的地址。任一检查失败都不写回执。

回执魔数 `KHUR`，内容是原简牍加上原始交易，原始交易最长 512 字节。

## 威胁模型

签名进程被设计成不能做的事，比检测恶意软件更窄，也更可检查。

| 攻击 | 清机的行为 |
| --- | --- |
| 页面或浊机给出一个哈希要求签名 | 没有该接口。输入不是 207 字节 `KHUB` 就拒绝 |
| 诱导 `approve` 或任意合约调用 | calldata 只能由资产种类推出，只能是空数据或 `transfer` |
| 改收款地址、数量、链编号、合约、费用封顶 | 确认串对不上，签名按钮保持禁用 |
| 用链上的代币符号、小数位或「官方」名称替换地址 | 清机不请求这些字符串，文本框里只有数字和全长地址 |
| 换保险库文件头，把 Argon2 改弱或把内存改得极大 | 参数必须等于 19 MiB、t=2、p=1，否则拒绝 |
| 简牍指定另一条派生路径 | 路径不在简牍里，代码里只有一条 |
| 投递目录里放符号链接，让写入截断保险库 | 写入使用新建文件，不跟随重解析点；目标名是链接时只删除链接 |
| 回执被换成另一笔已签名交易 | 浊机要求简牍字节和交易字段同时匹配才广播 |

仍然成立的边界：

- 清机和浊机若跑在同一个 Windows 账户下，该账户里的程序可以在解锁到签名完成的这几秒内读清机进程内存，也可以读口令框里尚未清掉的文字。要挡住这一点，清机和浊机分属两个普通账户，都不要是管理员。保险库在清机账户的用户目录里，日常账户不应有读权限。
- 清机源码不发起网络连接。Rust 标准库仍会链上 `ws2_32.dll`。出网控制是防火墙规则，不是导入表为空。
- 管理员在解锁瞬间读内存，不在这版的范围内。清机没有反调试，也不扫描其他进程。
- 确认串不绑定 nonce。同一组经济字段可以再签一笔。
- 浊机的小数位是用户输入的。清机显示的是乘完之后的整数。以清机文本框里的整数为准。

两个普通账户共用投递目录时，只授予这两个账户修改该目录的权限：

```bat
mkdir C:\KonghuDrop
icacls C:\KonghuDrop /inheritance:r
icacls C:\KonghuDrop /grant:r qinguser:(OI)(CI)M
icacls C:\KonghuDrop /grant:r %USERNAME%:(OI)(CI)M
netsh advfirewall firewall add rule name="Konghu Qing deny out" dir=out action=block program="D:\cursor\钱包\打开\qing.exe" enable=yes
runas /user:qinguser "D:\cursor\钱包\打开\qing.exe"
```

防火墙规则里的路径换成 `qing.exe` 的实际位置。`runas` 之后清机的保险库在清机账户的 `%USERPROFILE%\.konghu\`，不在日常账户下。

## 代码

| 路径 | 内容 |
| --- | --- |
| `crates/tablet` | 207 字节简牍、回执、十进制数量换算 |
| `crates/evm` | EIP-1559 编码、解码、与简牍核对。无密钥，无网络 |
| `crates/qing-core` | 保险库、BIP-39、确认串、签名 |
| `crates/dropio` | 写文件时不跟随符号链接 |
| `apps/qing` | 清机窗口 |
| `apps/zhuo` | 浊机窗口与 RPC |
| `apps/konghu` | 桌面入口 |
| `registry/evm.json` | 链编号、符号、小数位、https RPC。清机不读 |

```bat
cargo build --release -p konghu -p qing -p zhuo
```

使用 GNU 工具链时，PATH 里要有 `as.exe`。工程目录含中文时，把 `CARGO_TARGET_DIR` 设到纯英文路径再编译。编译产物拷到同一目录：`konghu.exe` 可改名为 `空毂.exe`，旁边放 `qing.exe`、`zhuo.exe` 和 `evm.json`。浊机优先读 exe 旁边的 `evm.json`。
