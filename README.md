# 空毂

空毂是一个用窗口操作的钱包。双击桌面上的「空毂」，或者双击仓库里的 `打开\空毂.exe`。这一下会打开三扇窗：空毂本身，加上清机和浊机。没有命令行。种子和网络不放在同一个进程里，所以清机和浊机仍是两扇窗，它们是一件钱包的两面。

- **清机**窗口标题是「清机 — 空毂」。创建保险库、解锁、读简牍、核对、签名，都在这一扇里。助记词只在这里出现一次。
- **浊机**窗口标题是「浊机 — 空毂」。选链、填收款地址和数量、写入简牍、广播回执，都在这一扇里。这里没有种子。

两扇窗之间不发消息、不走剪贴板、不互相启动。它们只通过一个投递目录交换两个固定名字的文件。

## 思想从哪来

小团队比不过大钱包公司的检测、元件和应急。继续在签名程序里加功能，再设法把这些功能保护好，是用自己的短处去碰别人的长处。空毂把问题倒过来：签名程序里少放东西，攻击者惯用的抓手就没有地方可抓。

这个倒转来自《道德经》第十一章，不是拿来当标题的。原文说三十根辐条汇入一个毂，毂的中间是空的，车才用得上；器皿和房子也是这样。「有之以为利，无之以为用。」辐条是实的，负责受力；毂的用处恰恰是它中间没有被填上。

对应到钱包：

- **有**，是链的差别。链编号、小数位、节点、人在窗口里填的数量。这些必须存在，否则无法转账。它们放在浊机，允许被改、被骗、被植入。浊机坏了，损失的是这一笔的内容，不是签名能力本身。
- **无**，是清机拒绝拥有的能力。不签任意摘要，不签任意调用，不做授权，不读链上名称，不加载插件，不自动更新，不保存会话。空不是少写了功能，是签名核故意不成为攻击程序可以调用的通用签名器。

硬件钱包早就用过「无」的一半：屏幕在另一台设备上，种子不进联网的电脑。空毂没有第二台机器。使用约束是同一台电脑，所以不能靠物理隔离，只能靠进程里没有那些接口，再加两个普通 Windows 账户把种子进程和联网进程分开。账户是退化了的气隙，不是气隙本身。

## 不签摘要

浏览器钱包被盗，常见的一步是页面让钱包签一段它不解析的哈希：`eth_sign`、任意 `personal_sign`、或表面是许可实际是 `permit` 的类型化数据。钱包一旦提供「给我一个 32 字节，我签名」这个接口，后面所有的确认框都是在补一个已经打开的洞。恶意页面可以让哈希对应任何交易，窗口上的文字由页面供应。

清机没有这个接口。浊机只能放下二进制简牍，清机用自己的代码把简牍还原成 EIP-1559 交易（类型字节 `0x02`，访问列表必须为空），自己算待签名哈希，再用 secp256k1 签。签完把原始交易解回来，字段必须和简牍一致，恢复出的地址必须等于这把种子在固定路径上的地址。低 `s`。对不上就没有回执。

简牍里没有哈希字段。浊机想偷换交易，只能改简牍上的可见字段，而那些字段会进清机窗口，也会进确认串。

## 简牍为什么是固定的 207 字节

自由调用数据是第二个通用接口。有了它，`transfer` 和 `approve`、向恶意合约的任意调用就只是选择子不同。清机若能签任意 calldata，浊机或网页就能让它签授权，授权会留在链上，以后不必再骗一次。

所以简牍不是「交易的一种编码」，而是唯一允许的句子。布局是大端，总长 [`TABLET_LEN`](crates/tablet/src/lib.rs) = 207。短一字节、多一字节、魔数不对、版本不是 1，都拒绝。

| 偏移 | 长度 | 字段 | 约束 |
| --- | --- | --- | --- |
| 0 | 4 | 魔数 `KHUB` | |
| 4 | 1 | 版本 | 只能是 1 |
| 5 | 1 | 家族 | 只能是 1，表示 EVM |
| 6 | 8 | 链编号 | 不能为 0 |
| 14 | 1 | 资产 | 1 主币，2 代币 |
| 15 | 20 | 代币合约 | 主币必须全零；代币不能为零，也不能等于收款地址 |
| 35 | 20 | 收款地址 | 不能为零 |
| 55 | 32 | 数量 | 最小单位，不能为零 |
| 87 | 32 | 费用上限 | 不能小于 `gas_limit × max_fee_per_gas` |
| 119 | 8 | 过期 | unix 秒；必须落在现在起 30 分钟以内。浊机写出时设为现在加 15 分钟 |
| 127 | 8 | nonce | |
| 135 | 8 | gas | 1 到 200000。浊机对主币用 21000，对代币用 120000 |
| 143 | 32 | `max_fee_per_gas` | 不能为零，不能低于优先费 |
| 175 | 32 | `max_priority_fee_per_gas` | |

资产种类决定调用数据，简牍里没有单独的 calldata 字段。主币：`to` 是收款地址，`value` 是数量，数据为空。代币：`to` 是合约，`value` 是 0，数据恰好 68 字节，选择子是 `transfer(address,uint256)` 的 `a9059cbb`。`approve` 的 `095ea7b3` 没有构造路径。

这是语法，不是策略。策略可以写成「我们不建议授权」，然后某个新功能再把授权加回来。语法是清机的代码里不存在那种句子。家族字节留着，是因为以后若要加非 EVM，也是在清机里加一个编死的纯函数，仍然由家族字节选定，而不是从磁盘加载插件。插件是把「无」重新填上的路：签名行为可以在不改清机的情况下被换掉。

回执魔数是 `KHUR`。里面是当初那张简牍，加上清机自己编出来的原始交易，原始交易最长 512 字节。浊机广播前做两件事：回执里的简牍字节必须等于自己刚写出的那一张；原始交易解出来的链、nonce、费用、收款、金额、调用数据必须和简牍一致。旧交易配新简牍配不上。

## 链的差别不进签名核

前排公链里，大多数不是另一套签名算法，而是同一套 EVM 签名配上不同的链编号、小数位和节点。兼容这些链，不需要清机认识它们的名字。

浊机读 [`registry/evm.json`](registry/evm.json)。每条记录是链编号、符号、小数位、节点。文件可以放在浊机旁边换掉。加载时拒绝超过 1 MB 或 5000 条的文件，只接受 https，外加本机的 http；链编号不能重复、不能为 0；小数位不超过 36。节点报上来的链编号必须和登记里的一致，否则这张简牍写不出来。清机不读这个文件。窗口上看到的是数字形式的链编号。登记表里的符号不会出现在清机上。

小数位只在浊机使用。人在浊机里按习惯写「1.5」，浊机按当时填的小数位乘成最小单位。清机只显示那个整数。链上的代币名称、小数位和「你将获得」之类的句子都不进清机。这些字符串是对方可以伪造的，地址投毒和假代币靠的就是它们。

费用也由浊机向节点问，再写进简牍。有 `baseFee` 时，单价取两倍基础费加优先费，否则取两倍 `gasPrice`。零费用链写成 1 wei，避免简牍因单价为零被拒。人在清机上看到的是最小单位的费用上限，以及 `gas_limit × max_fee_per_gas` 这个实际封顶。实际封顶才是这笔交易最多能烧掉的主币。

派生路径同样不进简牍。清机只用 BIP-39 的 12 个词（16 字节熵），空的 BIP-39 口令，路径 `m/44'/60'/0'/0/0`。口令加密的是本机熵，不是第 25 个词。简牍不能指定另一条路径，否则浊机可以让清机签出人以为不是这个账户的钥匙。

## 确认串来自同机窗口不可信

硬件钱包可以让人相信小屏幕，因为那块屏幕不在被感染的电脑上。空毂的两扇窗都在这台电脑上。另一个程序可以盖住清机，画一个一模一样的窗口，上面写攻击者的地址。人如果只是阅读窗口、再点一个按钮，点中的可能是盖在上面的那一层。

所以签名按钮默认是灰的。清机要求人输入一整串，并且这个输入框拒绝粘贴：

- 主币：`链编号/数量/实际封顶/收款地址`
- 代币：在实际封顶和收款地址之间再加代币合约

数量和实际封顶是最小单位的十进制。地址是 40 位十六进制，不带 `0x`，大小写无所谓。这串应当在打开简牍之前就写在自己的记录里。照着清机窗口抄，等于把确认交给可能已经被盖住的像素。

最初的设计只让人输入收款地址的末 6 位十六进制，用来证明眼睛看着的是清机而不是另一个窗口。末 6 位只有 24 比特。攻击者可以生成一个末 3 字节相同的收款地址；数量、链编号、合约和费用则完全不在这 6 个字符里。确认串改成现在这样，是因为那一次对清机本身的攻击打穿了末 6 位。全长地址和最小单位数量进了人必须打出来的句子。

确认串仍然不包含 nonce 和过期时间。同一句确认串可以签出第二笔经济字段相同的转账。这是当前边界：它挡住改收款人、改数量、改链、改合约、抬高费用封顶；它不挡住「再付一次同样的钱」。

## 保险库不能被换一份参数

盗到钱包文件之后，常见的下一步是把文件头里的口令派生参数改弱，使暴力破解变得便宜；或者把内存参数改得极大，让打开钱包的程序去分配攻击者指定的内存。清机把 Argon2id 写死为 19 MiB、2 次迭代、并行度 1。文件里的参数只要有一个不同，就拒绝打开，不存在「按文件头里的参数派生」。改一字节密文和口令错误是同一句「无法打开保险库」。磁盘上没有熵的明文。

保险库格式是 `KHUV`，版本 1，长度固定。口令 8 到 128 个字符，创建时输入两次。已有保险库时，创建按钮不会覆盖它。

## 两个窗口怎么交接

浊机的「写入简牍」把 207 字书写成投递目录里的 `inbox.khub`，并在浊机自己的配置目录留下副本，用来稍后核对回执。清机的「读取简牍」只读这个名字。窗口中部是只读文本框，列出家族、链编号、付款地址、收款地址、资产种类、最小单位数量、费用上限、实际封顶、nonce、gas、两种单价和过期时间。本地备注如果有，出现在对应地址下面。备注文件在清机账户的 `%USERPROFILE%\.konghu\labels.txt`，一行是 `40位十六进制` 加一个空格再加不超过 32 字的备注。含控制字符、双向覆盖或零宽字符的行丢掉，避免备注把后面的金额行排乱。

确认串对上之后，「签名」才可按。签完，种子从进程里清掉，回执写成 `outbox.khur`。若投递目录里的简牍仍然是刚刚签的那一张，清机把它删掉。浊机的「广播回执」核对之后调用节点的 `eth_sendRawTransaction`，状态框给出交易哈希。程序不去打开浏览器。

写出这些文件的代码不跟随符号链接。临时文件用随机名字，并且以「必须新建」的方式创建；目标若已是重解析点，只删除链接本身。这是为了堵住一种具体的偷换：投递目录里预先放好指向保险库的链接，清机一保存就把保险库截断。目录联接若把投递目录指到保险库所在的文件夹，写出去的仍是 `outbox.khur` 这个名字，不会变成覆盖 `vault.khuv`。

## 病毒仍然能碰到的地方

清机不扫描别的进程，不做反调试，不挂钩。同一 Windows 账户里的程序，仍可以在解锁后的那几秒读清机的内存，或读窗口里尚未清掉的口令。因此清机和浊机应分属两个普通账户，都不要是管理员。这不是产品上的第二个钱包，是让联网的那个账户读不到清机账户的保险库文件。

清机的源码不发起连接。Rust 标准库仍会链上 `ws2_32.dll`，所以出网要靠防火墙规则挡住这个 exe，而不是靠「程序看起来没有套接字」。已经是管理员、并且能在解锁瞬间读内存的程序，不在这版的空心所能挡住的范围内。把检测做进清机，会让毂重新被填满。

| 路径 | 职责 |
| --- | --- |
| [`crates/tablet`](crates/tablet/src/lib.rs) | 207 字节简牍、回执、人类小数到最小单位 |
| [`crates/evm`](crates/evm/src/lib.rs) | EIP-1559 的编码、解码、与简牍核对。没有钥匙，没有网络 |
| [`crates/qing-core`](crates/qing-core/src/lib.rs) | 保险库、BIP-39/BIP-32、确认串、签名 |

| [`apps/qing`](apps/qing/src/main.rs) | 清机窗口 |
| [`apps/zhuo`](apps/zhuo/src/main.rs) | 浊机窗口 |
| [`registry/evm.json`](registry/evm.json) | 浊机的链登记。清机不读 |

```bat
cargo build --release -p qing -p zhuo
```

GNU 工具链需要 `as.exe` 在 PATH 中。工程路径含中文时，把 `CARGO_TARGET_DIR` 设到纯英文目录再编译。把 `registry\evm.json` 放在浊机旁边，或在仓库目录里启动浊机。

两个普通账户共用投递目录时，只把改文件的权限给这两个账户。清机用 `runas /user:清机账户` 打开。保险库在清机账户的 `%USERPROFILE%\.konghu\vault.khuv`。浊机的设置在日常账户的 `%USERPROFILE%\.konghu-zhuo\`。禁止清机出网的防火墙规则要写清机 exe 的实际路径。
